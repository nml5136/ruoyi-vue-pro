# 景点资料交接 v1

当前没有自动采集、导入或发布接口。外部材料先离线交接并人工核验，不能直接写生产目录。

实际存储：`ilvy_place(id, payload)` 保留完整 JSON；读接口原样返回，筛选只读取明确已知字段。契约文件为 `schema/place-evidence-v1.schema.json`，本地示例为 `src/main/resources/local-examples.json`。此 schema 是交接格式，尚未接入正式导入校验器，不应据此宣称导入链路已验收。

- `type` 为主类型；`types` 保留附加类型，`themes` 是主题。筛选类型匹配主/附类型。
- `level` 是兼容现页面的展示字段，审核入库时必须由 `grade.status/value` 推导。`grade.appliesToPlaceId` 必须是本地点，景区建筑不得继承景区等级；`pending/expired` 显示待核实，不能推断未评级。
- `heat` 与官方等级独立，带口径、来源、窗口、更新时间；未知为 null。编辑推荐不是客流或游客评分。
- `sources[]` 保留原始 URL、标题、发布方、抓取时间、核验状态和支持的字段。`review` 保存核验、过期和审核状态。尚未核实的事实不得变成已知开放/免费/设施具备。
- `coordinates` 明确 WGS84/GCJ-02/BD-09、目标是中心/停车/车辆入口/步行入口，不能将不同对象坐标互换。无可信坐标为 null，不在客户端猜测转换。
- `media[]` 分清照片/全景/模型/音频/实时视频，并保存权利人、许可、商业与修改授权和审核状态。无许可不展示真实地点素材。
- 动态开放、费用、电话、库存和天气不能从游记、照片或模型常识补全。每个动态字段在后续内容发布模型中须有独立来源和有效期；当前开发样本统一待核实或明确标注演示。
- 外部资料应附疑点和冲突，不把核验失败记录丢弃。提交 JSON/JSONL 与源链接即可，不提交登录凭据、个人身份资料或侵权媒体。

当前 local 模式只加载 4 个虚构测试地点，不含陕西真实景点目录；`grade` 全部 pending，坐标 null，媒体为空。没有与 Grok 通信或导入外部资料。
